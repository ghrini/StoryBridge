# AI_USE.md — AI use disclosure for StoryBridge

This file is maintained throughout development. Rules for keeping it honest:

- Code or text generated by Claude and **not changed by the student** is listed as **AI-generated, unchanged**. It is never described as student-authored.
- The "student" fields below are filled in **by the student**, not by Claude. A blank means "not yet done", not "nothing to report".
- Nothing here is a claim about test results or measurements. Real numbers live in `eval/`.

## Runtime AI use (what the finished app does)

| Component | Uses AI? | Notes |
|---|---|---|
| Transcription | Yes, local only | Whisper model run on this computer through `faster-whisper`. Audio is not sent anywhere. |
| Grounding engine | No | Plain Python text matching (to be written by the student in Phase 2). |
| Storybook text and chapter titles | **Yes, Google Gemini (live, optional)** | Changed on 2026-10-21 at the student's request: the book must read as a story, not a literal transcript. Gemini (default model `gemini-3.5-flash`) receives the numbered transcript **text only (never audio)** and returns sentences that each cite their source lines. They enter the book as "needs review" and nothing is exported until a person approves, edits, or removes each one. A real storyteller's words are only sent if they specifically agreed AND the key is declared a paid plan (Google may use text sent through free keys to improve its products, and people there may read it). Without the key, or if Google cannot be reached, a saved/pre-written draft is used instead, so the app works offline. A successful live draft is saved to the project's `ai_draft.json` for offline replay. |
| Book body text | Drafted by AI, reviewed by a person | The book's title page says so. The "in their own words" positioning must be reworded accordingly. |

## Development AI use

Claude (Anthropic) is used through Claude Code as a coding assistant. (At runtime the app uses Google Gemini, not Claude; see the table above.) The student makes the product, privacy, and algorithm decisions. The grounding engine (Phase 2) is the student's core contribution: Claude may explain, write tests, and review, but does not write the engine.
