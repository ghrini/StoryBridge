# StoryBridge — rules for every Claude session in this repo

StoryBridge is a volunteer-assisted web app that turns a senior's recorded life story into a short illustrated keepsake book **in the senior's own words**, for SmileCard (the student's nonprofit). **It is for SmileCard only (student, 2026-11-24):** it began as a Congressional App Challenge entry and no longer is one, so do not bring up the contest, its deadline, or its rules.

## Authorship and honesty (highest priority)
- This must remain the **student's** project. Explain each module before and after helping implement it. The student makes product, privacy, and algorithm decisions.
- **Do not write or replace the grounding engine** (`backend/app/services/grounding.py`). Allowed: explain algorithms, suggest pseudocode, write tests, review, find bugs, help repair specific failures. Implement/approve core functions one at a time, only when asked.
- `structure.py` was written by Claude at the student's request and is logged as AI-generated. The student has not yet written any code; keep protecting their real contribution: the Phase 2 grounding engine, their labeled eval set, their decisions, illustrations, and video narration.
- Keep `AI_USE.md` current after every substantial contribution. Never call unchanged AI-generated code student-authored. Never tick the student's "can explain" boxes.
- **Commits (student's choice, 2026-11-22):** commit messages and pull request descriptions do not mention AI and have no `Co-Authored-By` line. How the project was built is recorded in `AI_USE.md` instead, which stays in the repository and stays current.
- **Commit address (student's choice, 2026-11-25):** commits use the student's own GitHub email, set in this repository's git settings. Vercel's free plan deploys only commits by the account owner.
- **Never fabricate** test results, measurements, stakeholder feedback, quotes, or citations. Report real numbers from real runs, labelled with what was measured.
- Do not expand scope without approval. Non-goals: auth/accounts, database server, cloud storage, payments, mobile app, live phone-call recording, multilingual interviews, AI-generated illustrations as a feature, any health/cognitive assessment.
- Do not claim StoryBridge is the first life-story app, that it improves health/memory/mood, or that AI transcription is perfectly accurate.

## Privacy and consent (non-negotiable)
- Record only with informed consent; facility permission for care-facility residents; never record someone who may be unable to give informed consent.
- Recordings and transcripts stay local (`data/`, gitignored). **Never commit real recordings or transcripts.** No cloud storage. No audio to external APIs without the storyteller's specific agreement. Prefer local transcription.
- Never put health details, addresses, financial details, or other people's private info in the book.
- Benchmarks and tests use the student's own voice or clearly-labelled synthetic audio, never someone else's voice without consent.
- Every generated draft carries this notice exactly: "Draft for review with the storyteller. Every sentence should be confirmed by the senior or their family before sharing."

## Product rules
- **STUDENT DECISION (2026-10-21), replacing the original brief's "LLM never writes body text" rule:** the book must read as a real storybook, not a literal transcript, so an AI provider MAY draft the storybook text from the transcript. Safeguards that stay mandatory: drafted sentences start as `flagged` ("needs review") and cannot be exported until a person approves, edits, or removes each one; every sentence cites the transcript lines it is based on; the grounding check (student-written, Phase 2) must flag changed or invented facts (numbers, names, dates, negations, new details); a real AI service receives transcript text only, never audio, and only with the storyteller's specific consent (`agreed_external_ai`), with the API key kept on the server only; the app must still work fully offline using a saved/pre-written draft (`ai_draft.json` or the synthetic fixture); the book discloses that AI drafted the text. The "in their own words" positioning must be reworded in the README and ARCHITECTURE.md to match (never claim the text is the storyteller's literal words once an AI has drafted it).
- **STUDENT DECISION (2026-11-22), replacing per-sentence approval:** approving every line was "too much"; instead a person reads the story and types change requests into a chat box ("Ask for changes"; the AI rewrites the book), then presses one "The story is right" button. Safeguards that stay: nothing can be exported until the story is confirmed; after any change only the new or changed sentences are marked "changed" and must be confirmed again; the per-sentence tools (Play source, Edit, Take out) remain, folded under each page ("Fix this page by hand"); the chat uses the same outside-AI gate as drafting. A sentence based only on the reviewer's own message may have no source lines (shown as "From a message you sent"; a page with no source lines gets no QR code).
- Unconfirmed sentences cannot be exported until a person confirms the story or fixes them by hand. Grounding flags use icons plus text, never colour alone. Sentences a person rewrites are recorded as `volunteer_caption`; AI sentences as `ai_draft`.

## Stack and Windows conventions
- Backend: Python 3.11 venv at `.venv` (`py -3.11 -m venv .venv`), FastAPI, Pydantic, faster-whisper (CPU, int8), rapidfuzz, reportlab, qrcode, pytest. ffmpeg is called directly with `subprocess` (no pydub). No WeasyPrint.
- Frontend: React + Vite, JavaScript with JSDoc, plain CSS, Vitest. Storage: JSON files under `data/`.
- Run Python as `.\.venv\Scripts\python.exe ...` instead of relying on venv activation. In an already-open terminal, refresh PATH after installs: `$env:Path = [Environment]::GetEnvironmentVariable("Path","Machine") + ";" + [Environment]::GetEnvironmentVariable("Path","User")`.
- The Whisper model cache is `models/` (gitignored).
